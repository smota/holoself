# Holoself 0.10.0

Holoself keeps personal memory separate from the domains that use it. Context, search and indexing now read only self records; each domain maintains its own content and index.

## Self-owned lenses

Every lens lives in the self's `lenses` directory with the same definition format. The self binds projects to allowed lenses through `lenses/bindings.json`. `professional` replaces `career`, and `public-voice` replaces `publishing`. The private lens remains owner-exclusive. Public voice uses ordinary access rules without the retired publishing-specific eligibility filters. Memory proposals still require approval.

CLI, MCP and Workbench share the binding contract. Workbench discovers spaces from bindings and removes stale registry entries.

## Reviewable migration

Maintenance previews exact before/after content and hashes. Applying a reviewed plan requires its digest; receipts support safe replay and recoverable failures roll back previous writes. Historical proposals and receipts remain unchanged. Link approval and backfill preserve the separate attestation contract.

Back up data before migration. Preview and apply the lens migration, then repair project links and update consumers that explicitly request legacy lens IDs. See the [CLI reference](../reference/cli.md) and [adoption and rollback runbook](../guides/adoption-and-rollback-runbook.md). Missing bindings fail closed.

## Validation and limits

Repository verification passed locally: 245 tests passed, zero failed, one optional D01 spike test skipped; package audit, help and capabilities passed. A backup-copy rehearsal validated migration, proposal preservation, link repair and context. Workbench has API and static test coverage; no browser visual review was performed. Rollback covers recoverable failures, not abrupt process termination. The release does not migrate data automatically.
