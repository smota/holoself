# Holoself 0.12.0

Holoself now works across machines where your self root and projects sit at different paths, moves field and claim rules to the lens vocabulary, and corrects how heading rules and proposal previews protect hidden text. Read the upgrade notes before installing.

## Portable links

A linked project no longer stores the absolute path of your self. A self root has a stable `self_id`, a project has a stable `project_key`, and `link.yaml` records those. Each machine keeps its own `selves.json` that maps a `self_id` to the local checkout, managed with `holoself machine status`, `machine register` and `machine forget`. `lenses/bindings.json` is keyed by project, so one entry serves every machine.

Holoself finds the self through `--self` or `--root`, then `HOLOSELF_HOME`, then `selves.json`, then a legacy path. It checks the `self_id` every time and refuses with `SELF_NOT_FOUND` rather than guessing. Approval stays per machine: a cloned project cannot approve itself. See [multiple machines](../guides/multiple-machines.md) and the [decision record](../decisions/portable-links.md).

## One rule for grants

A synced file can no longer widen what a project may read on this machine. On an existing project a grant narrows automatically, and it widens only when you name lenses on the command or pass `--accept-shared-lenses`. `--yes` alone never widens, and this holds for `link setup`, `add`, `repair`, `approve`, `backfill` and the Workbench. `link backfill` never reactivates a revoked link. `link remove` keeps a shared lens binding for your other machines; `lens unbind` removes it everywhere.

## Field and claim rules in the lens vocabulary

The runtime reads `field_access` and claim markers such as `<!-- holoself-claim access_lenses=general,private disclosure=review-required -->`. `holoself migrate policy` rewrites `field_visibility` and `visibility=` markers to these forms, with a reviewable plan and a byte-identical revert. It leaves out, with a warning, any document it cannot rewrite safely. `validate --fix` prints the mapping for each file and hands off to `migrate policy --dry-run`. Approved proposals write the new marker. Legacy forms keep working in this release; 0.13.0 rejects them.

## Corrections to released behaviour

These correct earlier versions, so review documents that rely on field rules:

- From 0.6.0 through 0.11.1, some text under a heading hidden by a field rule could reach callers the rule excluded. A heading rule now covers the claims and deeper headings beneath it on every output path, and it ends only at an unambiguous real heading. Unusual heading shapes hide more rather than less.
- In 0.11.0 and 0.11.1, an MCP proposal preview could return claim text that delivery had removed. Previews are now built from delivered text.
- Non-owner callers and publication adapters no longer receive rule details, custom lens names or hidden field names.

Documents with field rules can show less than before, and section splits and ids can change. A security advisory follows this release.

## Upgrade notes

- **Upgrade every machine before running `holoself link repair` on any of them.** Older versions cannot read repaired links or project-keyed bindings.
- The catalog schema is now version 5; catalogs rebuild once on first use.
- On each machine, run `holoself link repair --project <dir>` in linked projects. Review any note about lenses a shared binding would add.
- Preview `holoself migrate policy --dry-run` before applying it.
- In client projects, keep per-machine files out of git, as the [guide](../guides/multiple-machines.md) lists.

## Validation and limits

Repository verification passed in CI on Linux, Windows and macOS, and every change had independent review. Multi-machine behaviour was tested with simulated machines, not on separate computers. The Codex and AGY session-start hooks remain unverified in a live run. Cross-script homoglyphs in heading names are not matched. `export --target` copies source documents as they are, including lines hidden by field rules. This release does not migrate data automatically.
