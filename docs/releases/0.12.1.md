# Holoself 0.12.1

This patch removes seven OpenTelemetry packages from user installations and documents the optional operation telemetry already present in the npm 0.12.0 package.

## Installation dependencies

The seven OpenTelemetry dependencies are now development tooling and are no longer installed with Holoself. Product operation telemetry uses Node's built-in HTTP support.

## Operation telemetry

The npm 0.12.0 package was built after the tag and also contains operation telemetry from #140, absent from the 0.12.0 release notes.

Telemetry stays off unless `~/.config/observability/consumer.env` exists with a valid loopback endpoint and `http/protobuf` protocol. Export uses literal loopback HTTP only. Spans contain fixed service identity `holoself`, timing, correlation IDs and operation outcomes such as `success` or `error`. They contain no command or tool names, arguments, paths, content or client identity.

Set `HOLOSELF_TELEMETRY=off`, `OTEL_SDK_DISABLED=true` or `OTEL_SDK_DISABLED=1` to opt out. Removing the consumer file also disables export; restart an MCP server to pick up configuration changes. See the [telemetry guide](../guides/telemetry.md) for collection and activation details.

## Security fixes

The security fixes shipped in 0.12.0 are unchanged. Version 0.12.0 remains the patched version in [GHSA-hrc3-wgqf-mvhq](https://github.com/smota/holoself/security/advisories/GHSA-hrc3-wgqf-mvhq).

## Upgrade notes

Run the npm install command again:

```bash
npm install --global holoself-ai
```

No other upgrade action is needed for this patch.
