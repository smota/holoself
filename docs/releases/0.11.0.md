# Holoself 0.11.0

Holoself now reaches AI tools through MCP by default, lets you correct what it knows through review, and closes several privacy gaps found during an end-to-end review. Read the upgrade notes before installing.

## MCP-first delivery

`link setup`, `link add`, `link activate` and `link repair` configure the project-local MCP server for every host verified in `docs/reference/platform-verification.json`: Claude Code, Codex and AGY. Read-only tools can be pre-approved with `--approve-read-tools`; `proposal_create` always asks. `holoself mcp` runs tool calls on a small worker pool with cancellation, timeouts and backpressure, so a slow call no longer blocks the session.

Session-start hooks give the AI a context packet before the first prompt. Claude Code hooks are verified and installed by default. Codex and AGY hooks are available with `--hooks` until a live run confirms them; Codex asks you to trust `.codex/hooks.json` once. Hook mode never blocks a session: it prints only the packet, stays under 9,000 bytes and prints nothing on refusal.

Desktop MCP clients without a project can register their own identity with `holoself client add` and run `holoself mcp --client <name>`. Each client gets its own lenses and a separate proposal inbox.

Every served packet appends a metadata-only line to a local ledger in the project's `.holoself/` directory, so you can see which AI received which context. Task text is stored only as a keyed hash.

## Correcting knowledge

Proposals can now replace, supersede or retire an existing claim, not only append new ones. The Workbench review inbox groups pending proposals across spaces, flags near-duplicates and conflicts, and approves or rejects a batch atomically. An MCP prompt helps an AI harvest proposals at the end of a session.

## Privacy defaults and repair

A `_policy.yaml` file sets privacy defaults for a directory; documents override them field by field, and documents using the legacy `visibility` field are not affected. `holoself validate --fix` plans digest-bound repairs for documents excluded for missing metadata, never widening existing values. Doctor, validate and the Workbench Overview show how many documents are excluded.

The privacy fields are being consolidated ([decision](../decisions/privacy-fields-and-legacy-mount.md)). In 0.11.0, `validate` warns about deprecated fields and `holoself migrate policy` maps `visibility` and `public_safe` exactly. Later releases rewrite field and claim markers (0.12.0), reject deprecated fields (0.13.0) and remove them from the schemas (0.14.0).

## Retrieval

When Node.js provides `node:sqlite` with FTS5, context ranking adds BM25 scoring over the documents the caller may see. A synthetic evaluation set gates retrieval in CI: recall rose from 0.77 to 0.85 with the built-in index and 0.875 with FTS5, with zero privacy leaks. `holoself context --need required|helpful|not-needed` overrides the inferred context need. Paraphrased queries remain a known weakness.

## Security fixes

- The Workbench answers only loopback `Host` headers and requires its session token on every API request, closing a DNS-rebinding exposure. A security advisory will follow this release.
- Public adapters now apply claim- and field-level restrictions to delivered content, snippets and search.
- `holoself migrate policy` can no longer widen access, and migrating documents the catalog currently excludes requires `--confirm-activation`.
- Claim markers fail closed when malformed, and proposal text can no longer inject markers or change IDs.
- Audit logs, plans and policy files are written with mode `0600`, and existing file modes are preserved.

## Upgrade notes

- Node.js 22 or newer is required.
- The catalog schema is now version 3; catalogs rebuild once on first use.
- Run `holoself link repair` in linked projects to add MCP configuration and hooks. Existing Codex configurations need the repair to enable `holoself_context`.
- Run `holoself validate` to see deprecation warnings, then preview `holoself migrate policy --dry-run`.

## Validation and limits

Repository verification passes on Linux and Windows in CI and locally; macOS ran as an advisory check during a GitHub runner outage, and the release workflow requires it. A synthetic 83-case packet-parity harness guarded the core module split. MCP use was verified natively in Claude Code, Codex and AGY; Codex and AGY hooks were not run live. This release does not migrate data automatically.
