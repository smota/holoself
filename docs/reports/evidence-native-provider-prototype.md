# D02 native filesystem provider: bounded foundation

Status: **provider foundation test snapshot, not D02 acceptance** (2026-09-28). An integrated D02 candidate was added on 2026-09-29; the handoff observations below describe the foundation at the time. Current integrated tests cover the CLI, domain transactions, setup/recovery, and retained-handle enumeration. Windows Node 24 has an unresolved intermittent native process-exit assertion after successful CLI publication, so this report makes no D02 acceptance claim.

## Contract for integration

`loadEvidenceFilesystem()` lazily loads pinned optional `koffi@3.3.2` (MIT, platform binaries in optional npm packages). There is no startup installer or path-based fallback. Unrelated CLI commands do not load it. An absent or unsupported binding reports `EVIDENCE_FS_UNAVAILABLE`. Ordinary native failures preserve native status and use stable codes: `EVIDENCE_FS_MISSING`, `_EXISTS`, `_BUSY`, `_DENIED`, `_UNSAFE`, or `_IO`; availability is reserved for a missing/unsupported capability. The package lock records the binding, but a deployment must explicitly install its optional platform package.

The provider returns retained directory, file, and lock handles. The caller owns each returned handle and calls `provider.close(handle)` in reverse order. Keep each parent handle open while operating on children. `openAbsolute` is a no-follow component-walk primitive, **not** evidence-root authorization. Use `openSetupParent(path)` to authorize an existing parent before creating a private root, or `openEvidenceRoot(path)` to authorize an existing private root. Call `assertBound(root)` at sensitive phase boundaries to detect a moved or replaced locator. `openRelativeDirectory`, `openFile`, `createDirectory`, `createFile`, `read`, `write`, `flush`, `stat`, `identity`, `publishNoReplace`, `replace`, `unlink`, `removeDirectory`, and `lock` operate through retained objects. The persistent lock handle must span revision checks, publication, and cleanup. Setup self-config writes need the same object-bound staging and replacement procedure.

The native provider does **not** return a validated string for Node to reopen. Windows uses `NtCreateFile` with `RootDirectory` and `FILE_OPEN_REPARSE_POINT`, checks reparse tags on the opened object, uses native handle I/O, and publishes with `NtSetInformationFile` relative to a held destination directory. POSIX uses `openat`/`mkdirat`/`linkat`/`renameat`/`unlinkat`; a POSIX native descriptor is also a Node descriptor, unlike a Windows `HANDLE`. Source opens are no-follow and nonblocking before regular-file validation, so a FIFO replacement cannot stall an import. `stat` exposes held-object size and change indicators for caller-side pre/post read checks. Created stages are exclusive and restrictive before bytes are written. Publication is immutable no-replace; manifest replacement is atomic. A POSIX crash between `linkat` and stage `unlinkat` can leave both names, so transaction recovery must recognize the owned stage.

Root authorization checks local filesystem capability, owner, ancestor replacement authority, and private-root access. POSIX checks mode and owner plus ancestor replacement rights; on macOS it also iterates extended ACL entries and rejects allow/unknown entries that it cannot safely authorize. Windows obtains owner and DACL from the **opened handles**, treats current owner, SYSTEM, Administrators, and TrustedInstaller as owner-equivalent administration, rejects non-owner replacement grants on ancestors and non-owner access grants on a private root, and creates private roots/children/stages with a protected owner/SYSTEM/Administrators full-control descriptor at creation. It qualifies fixed NTFS/ReFS volumes with persistent ACLs. An unknown ACE or filesystem capability fails closed. `C:\Users\samue\AppData\Local\Temp` is intentionally rejected as a Windows setup ancestor on this host because an untrusted group has replacement authority. Tests create a unique private fixture under the validated user home and modify only that fixture's ACL.

An owner-equivalent OS actor can move an already-open root; retained handles keep operations on the opened objects, and `assertBound` detects the changed locator when invoked. The provider cannot revoke owner-equivalent OS authority. Same-owner malicious concurrent mutation therefore remains inside the declared trust boundary. The future caller must verify the configured root's marker/identity and its overlap with private self/project roots, detect case/normalization collisions, enforce the accepted 50 MiB input ceiling, hash the opened source, and implement H5 revision/idempotency/transaction recovery. No caller may bypass root authorization with `openAbsolute` for evidence storage.

## Remaining qualification

At the foundation handoff, macOS code paths (including `fstatfs` local APFS/HFS qualification, ACL iteration, and Darwin-specific flags) and Windows ARM64 ABI guard were **unexecuted**; this report does not claim support on those hosts. The macOS `statfs` layout and ACL end-of-iteration behavior were checked against Apple headers/manuals but need a real macOS run. More filesystem variants and Windows reparse tags also need platform qualification. The WSL checked-in tests injected the isolated dependency prefix; the installed-package test was completed during the integration update below. A full D02 acceptance review must assess the integrated behavior separately.

Primary API references: [Koffi pointers](https://koffi.dev/pointers), [POSIX openat](https://man7.org/linux/man-pages/man2/open.2.html), [Apple statfs layout and flags](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/mount.h), [Apple acl_get_entry](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_entry.3.html), [Windows NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [Windows GetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo), [Windows file rename information](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information), [Windows NtSetInformationFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntsetinformationfile).

## Integration update (2026-09-29)

The provider now enumerates names from retained directory handles for case/normalization collision checks. Windows-created private directories carry inheritable owner/SYSTEM/Administrators grants so new `init` files remain private. The integrated synthetic CLI tests cover setup recovery, hash revisions, consented snapshots, withdrawal, privacy in ordinary context/export, and two-process expected-revision publication. Exact Windows Node 20.0.0 targeted tests: 15 total, 13 pass, 2 platform skips, 0 fail. An installed package on WSL Ubuntu Node 20.0.0 passed normal CLI init, setup, register, inspect, and withdraw. This update does not qualify macOS or ARM64.

Bundled Windows Node 24.19.0 full verification was intermittent: one run passed 253 of 255 tests with 2 skips, while a later run failed one CLI child after it printed a successful snapshot registration. The child exited `0xC0000409` with `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` in `src\win\async.c:94`. An isolated official Node 24.20.0 comparison also reproduced the assertion. No runtime remedy or causal attribution is established; D02 requires further qualification and independent review before acceptance.
