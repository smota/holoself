# Framework Orchestration — Leading with the Right Lens

## What it does

When multiple communication and reasoning frameworks apply to the same output, this overlay determines which one leads and how the others support it. Prevents framework collision and ensures the output serves the audience's actual decision-making need.

## The four frameworks and their roles

| Framework | Role | Layer |
|-----------|------|-------|
| Systems Thinking | Informs the insight — what is actually happening in the system | Analysis (before structuring) |
| Minto Pyramid | Structures the argument — conclusion-first, MECE, defensible | Logic (the skeleton) |
| ABT | Shapes the narrative — context, tension, resolution | Story (the arc) |
| Minto SCQA | Governs the communication — for emails and written invitations | Delivery (the wrapper) |

## How to decide which framework leads

Ask: **what does this audience need from this output?**

- **They need to make a decision** → Pyramid leads. State the recommendation. Structure the case.
- **They need to understand a situation** → ABT leads. Establish context, surface the tension, drive to the action.
- **They need to act on an email or invitation** → SCQA leads. Weave the narrative. Bury the framework.
- **The problem is more complex than it appears** → Systems Thinking runs first (silently), then the appropriate output framework takes over.

The frameworks are not sequential. Systems Thinking informs the content before any framework is applied. The output framework is chosen based on format and audience — then the others support it underneath.

## Practical rule

Lead with one. Use the others as structural support. Never stack visible frameworks — the output should show only the thinking, never the scaffolding.

When in doubt: if the reader needs to decide, Pyramid. If the reader needs to understand, ABT. If the output is an email, SCQA.
